## Module by module

### `error.rs`

A single `Error` enum for the whole crate, with 7 variants:

- **`UnknownModel { model_id }`** — the payload's `model_id` is not in the registry.
- **`InvalidDim { expected, got }`** — the payload size (in bytes) does not match the declared dimension for this model.
- **`InvalidNumeric`** — the vector contains a `NaN` or `Inf`.
- **`Vdb(String)`** — error returned by the Qdrant client.
- **`Config(Box<figment::Error>)`** — config parsing/loading error. Boxed because `figment::Error` weighs ~200 bytes.
- **`Io(std::io::Error)`** — I/O error at startup.
- **`Validation(String)`** — failure of post-parse config validation rules.

`From` conversions derived via `#[from]` for `io::Error` and `figment::Error`.

The hot-path variants (`UnknownModel`, `InvalidDim`, `InvalidNumeric`, `Vdb`) match the `status` labels of the `requests_total` metric.

### `config.rs`

The full configuration schema, broken into sub-structs:

- **`Config`** — root.
- **`ServerConfig`** — listen addresses, rate / payload limits.
- **`AdminConfig`** — bearer token.
- **`VdbConfig`** — URL, timeout, retry.
- **`PoolConfig`** — buffers-per-worker factor.
- **`TelemetryConfig`** — log level, OTLP endpoint.
- **`ModelSpec`** — `{ dim, normalize, vdb_namespace }`, stored in the registry.

Loading via `figment`:
- `Config::load(path)` reads a TOML then applies env overrides (`VR_*`, separator `__` for sub-fields).
- `Config::from_figment(fig)` exposes the injection for tests.

After parsing, `validate()` checks:
- `admin.bearer_token` non-empty.
- `vdb.url` non-empty.
- `pool.buffers_per_worker ≥ 1`.
- `vdb.max_retries ≥ 1`.
- For each model: non-empty name, `dim ≠ 0`, non-empty `vdb_namespace`.

11 unit tests cover every error case and the minimal valid configuration.

### `registry.rs`

The registry is the source of truth for allowed models. It is accessed on every gRPC request, hence the read-side optimization.

**Internal structure**: `ArcSwap<HashMap<String, ModelSpec>>`. `ArcSwap` enables lock-free reads (each reader clones an `Arc`, takes no lock).

**API**:
- `new(initial)` — creates the registry with an initial content.
- `get(id)` — O(1) lookup, returns a copy of the `ModelSpec`.
- `snapshot()` — returns the `Arc<HashMap>` for a multi-entry traversal without race.
- `upsert(id, spec)` — inserts or replaces, via `ArcSwap::rcu`.
- `remove(id)` — removes, returns whether the entry existed.
- `list()` — returns a Vec of the current entries.

**About `rcu`**: `rcu` = Read-Copy-Update. To update: load the snapshot, clone the map, modify the copy, swap atomically. If another update happens between load and swap, `rcu` retries automatically. Amortized cost ≈ cost of a read + clone + swap. Under rare updates (admin, a few per hour), contention is essentially zero.

**Critical rule**: in a gRPC handler, call `snapshot()` or `get()` **only once** per request. Otherwise, two lookups can land on either side of an update and observe inconsistent registry versions (e.g. model found on the first read, gone on the second).

**loom test**: validates the pattern "snapshot via Arc clone + update via swap" on a simplified `Mutex<Arc<T>>` model (not directly `ArcSwap`, which has its own internal loom coverage). See `DECISIONS.md`.

### `pool.rs`

The pool amortizes memory allocation in the case where the protobuf payload arrives misaligned and must be copied into an aligned buffer.

**`AlignedBuffer`**:
- Storage as `Box<[u32]>` — guarantees alignment 4 (natural size and alignment of `u32` and `f32` are identical).
- `len: usize` — usable length in bytes, independent of capacity.
- `copy_from_slice(&[u8])` — copies into the buffer, updates `len`.
- `as_f32()` — returns `&[f32]` via `bytemuck::try_cast_slice` (which can only fail if `len` is not a multiple of 4).
- `clear()` — resets `len` to 0 without deallocating.
- `Default` — empty buffer (sentinel for `mem::take` in `PooledBuffer`'s Drop).

**`BufferPool`**:
- `queue: ArrayQueue<AlignedBuffer>` — pre-allocated with `size` buffers at creation.
- `take()` → `PooledBuffer<'_>` — pops from the pool, or allocates as a fallback if empty (increments `exhausted_count`).
- **Never blocks**. A load-correlated block would degrade p99 exactly under contention.

**`PooledBuffer<'p>`**:
- Dereferences to `AlignedBuffer` (`Deref` / `DerefMut`).
- **Drop**: `mem::take(&mut self.buffer)` swaps in an `AlignedBuffer::default()` (empty, zero alloc), then the extracted buffer is cleared and pushed back onto the queue. If the queue is full (case where the pool previously fallback-allocated), the buffer is simply dropped.

**Important invariant**: a `PooledBuffer` always owns a valid `AlignedBuffer` from construction to Drop. This avoids the `Option<AlignedBuffer>` pattern that would have forced an `.expect()` in `Deref` (forbidden by project rules).

**miri green** on all tests — no UB in the `u32 ↔ u8` casts.

### `math.rs`

The numerical kernel. Three public functions, all synchronous and decoupled from the rest of the service.

**`validate_and_align(raw, expected_dim, scratch) → Result<Cow<[f32]>, Error>`**:

1. Computes `expected_bytes = expected_dim × 4` (with `checked_mul` to avoid any wrap).
2. Checks `raw.len() == expected_bytes`, otherwise returns `InvalidDim`.
3. Attempts `bytemuck::try_cast_slice::<u8, f32>(raw)`:
   - **Success** → `Cow::Borrowed(slice)`. Zero-copy. The majority case in practice.
   - **Failure** (misalignment, length is already validated) → copies into `scratch`, returns `Cow::Borrowed(scratch.as_f32()?)`. One copy, that's it.

The returned `Cow` is `'a`: lifetime tied to the shorter of (`raw`, `scratch`), unified under `'a` in the signature. The caller does not distinguish between zero-copy and copy.

**`l2_norm_squared(v) → Result<f32, Error>`**:

One pass over `v`. For each element:
1. If non-finite (`!x.is_finite()`, i.e. NaN or ±Inf) → `InvalidNumeric`.
2. Otherwise, accumulate `sum += x × x`.

Returns `Σ xᵢ²`. We compute the square (not the root) to avoid a useless `sqrt`: the comparison against 1 to decide on normalization can be done on the square directly.

Fused validation + sum: a single traversal of the vector instead of two (vs doing an `iter().any(|x| !x.is_finite())` followed by an `iter().map(|x| x*x).sum()`).

`#[inline]` to maximize the chances of caller-side auto-vectorization.

**`normalize_in_place(v, norm_squared) → bool`**:

1. If `|norm² − 1.0| ≤ 2×10⁻⁶` → nothing to do, returns `false`.
2. If `norm² ≤ 0.0` → zero vector, nothing to do, returns `false`.
3. Otherwise, `norm = norm².sqrt()`, then `v[i] /= norm` for each `i`. Returns `true`.

The boolean return indicates whether a division actually happened (useful for the `normalizations_performed_total` metric).

**Tests**: 13 cases cover aligned zero-copy, misaligned with forced copy (via `[u32; 5]` backing for miri), wrong size, NaN, Inf, end-to-end pipeline. **miri green**.

## How the modules fit together

The service exposes two gRPC RPCs: `Upsert` (write) and `Search` (read). The two share **exactly the same validation and normalization pipeline**; only the final Qdrant operation and the response shape differ.

### Shared Upsert/Search pipeline

The pipeline code is to be extracted into a helper function, called by each handler:

```
1. registry.get(&request.model_id)
      → None          → returns Error::UnknownModel
      → Some(spec)    → continue

2. if request.dim as usize != spec.dim { return Error::InvalidDim }

3. let mut pooled = pool.take();

4. let view = math::validate_and_align(
       &request.vector,
       spec.dim,
       &mut pooled,           // scratch, used only if misaligned
   )?;

5. let n2 = math::l2_norm_squared(&view)?;

6. let vector_owned: Vec<f32> = if spec.normalize {
       let mut owned = view.into_owned();
       let changed = math::normalize_in_place(&mut owned, n2);
       // (mark in the response: was_normalized = changed)
       owned
   } else {
       view.into_owned()
   };
   // pooled can now be released, the Qdrant await can proceed
```

At this point, `vector_owned` is ready to be sent to Qdrant, regardless of the RPC.

### Upsert divergence

```
7a. qdrant.upsert_points(
        collection = spec.vdb_namespace,
        point_id   = request.point_id,
        vector     = vector_owned,
        metadata   = request.metadata,
    ).await?

8a. UpsertResponse {
        point_id,
        processing_us,
        was_normalized,
        vdb_namespace: spec.vdb_namespace,
    }
```

### Search divergence

```
7b. let hits = qdrant.search_points(
        collection       = spec.vdb_namespace,
        vector           = vector_owned,
        limit            = request.limit,
        score_threshold  = request.score_threshold,
        filter           = request.metadata_filter,
    ).await?;

8b. SearchResponse {
        hits: hits.map(|h| SearchHit {
            point_id:  h.id,
            score:     h.score,
            metadata:  h.metadata,
        }).collect(),
        processing_us,
        was_normalized,
        vdb_namespace: spec.vdb_namespace,
    }
```

### Why sharing the pipeline is critical

Cosine similarity search assumes that **all compared vectors are normalized to the same norm** (typically 1). If the database holds normalized vectors but the query vector is not (or vice versa), scores are systematically biased.

By routing both flows through the same function that respects `spec.normalize`, we guarantee that query and documents live in the same space. That is the key invariant of functional consistency.

At step 7, this pseudo-code will be refined to handle the `view → owned` transition efficiently (see Risk 1 in `HANDOVER.md`).

## Invariants to preserve

These properties are guaranteed by the current code and must be preserved by any modification.

1. **No `unsafe`** outside `bytemuck` usage (which is itself safe).
2. **No `unwrap` / `expect`** outside `main.rs`, test modules, benches, and `build.rs`.
3. **No allocation in the hot path outside misalignment** (and in that case, a single copy per request via the pool).
4. **`validate_and_align` never panics** — always returns a `Result`, even on weird input.
5. **The pool never blocks** — exhaustion = one-off allocation, not waiting.
6. **The registry never exposes partial state** — each `load()` returns a complete atomic snapshot.
7. **Benches use `black_box` on inputs and outputs** — when adding a bench, follow this rule or the numbers will be wrong.

## Test strategy

**Unit tests** (`#[cfg(test)] mod tests` in each module) — cover the functional behavior of every public function, including explicit edge cases (NaN, Inf, zero vector, empty registry, oversize payload, misaligned slice).

**loom test** (`#[cfg(loom)]`) — validates that a concurrent reader of an update never observes corrupted state. Run manually via `RUSTFLAGS='--cfg loom' cargo test`.

**Miri** (`cargo +nightly miri test`) — checks the absence of UB in the `math` and `pool` modules (the ones manipulating raw memory via `bytemuck`).

**Criterion benches** — measure execution times with `black_box` on inputs and outputs, plus built-in sanity assertions to detect any compiler elimination.

**Integration tests** (to be added at step 10, in `tests/`) — exercise the full pipeline through the gRPC server.
